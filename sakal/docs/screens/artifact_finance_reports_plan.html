Finance Module · Reporting Blueprint

Eight reports, closing the real gaps

Finance already covers all four core statements plus AR/AP — this isn't a from-zero build like Purchase was. What's missing is a chronological "everything that happened" register, the two tax-compliance reports a DRC/Zambia business actually needs to file, comparative period-over-period analysis, and a couple of fast operational snapshots. Every report below is either cross-module GL data no other report currently surfaces, or an additive widening of an existing function — nothing here duplicates what's already built.

02

VAT / Tax Return Summary

Grouped

Output Tax vs Input Tax vs Net Payable/Refundable for a period — the standout compliance report for DRC/Zambia filing. Sourced straight off the GL, not any one module's own tax fields.

Filters

Date range — required Tax
Column
GroupTax Code/Name · Output Tax Amount · Input Tax Amount · Net Payable
DetailSource Doc Type/No/Date · Account · Amount
Cross-module by construction: reads rid_finance_lines filtered to accounts matching each tax's own gl_output_account_id/gl_input_account_id — Sales, Purchase, and Expense all converge here automatically, no per-module wiring.
03

Withholding Tax Summary

Grouped

Which suppliers had WHT deducted, and how much — the basis for issuing a WHT certificate. One row per supplier, expanding to the bills it was deducted on.

Filters

Date range — required Supplier
Column
GroupSupplier · Gross Amount · WHT Amount · WHT %
DetailBill No · Bill Date · Tax Code · WHT Amount
Filters rid_finance_lines on source_line_type = 'WITHHOLDING' — already tagged by Expense Voucher's own posting function (migration 107), no new tagging needed.

Comparative Profit & Loss

The same account tree as Profit & Loss Account Detail, with the immediately-preceding period's figure and variance added alongside — not a new report shape, an additive widening of the existing function.

Filters

The Hierarchical engine already renders multiple numeric columns per tree row — Balance Sheet's own dual Base/Local columns prove it — so this is CREATE OR REPLACE FUNCTION appending columns, never a new report type.
