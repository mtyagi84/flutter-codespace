Master Data · Reporting Blueprint

Thirteen reports, one free capability

No master screen anywhere in the app has a Print or Export button today — this is a genuinely greenfield feature, confirmed by direct code search. But the generic reporting engine already gives any registered report a letterheaded PDF export and an Excel export for free, with zero new Flutter code — so "Master Data Printing" is really just registering these 13 masters the same way Purchase, Sales, and Finance's transactional reports already were.

Design decision Chart of Accounts, Chart of Groups, and Item Categories are all self-referencing trees — but they're built as Tabular reports with a computed indent (repeat(' ', level_depth) || name), not the existing Hierarchical report type. That renderer is hardcoded to a single monetary amount column per row (built for P&L/ Balance Sheet) — a pure structural tree with nothing to sum doesn't fit it. A plain indented list prints cleanly and needs no new widget work.

Pricing

The highest operational value in this batch, and the only structurally different report
13

Price List Report

Grouped

A physical, printable price sheet — real SME value (showroom/agent handouts). Scoped as a batch register for v1: one row per Price Master entry (batch), expanding to its own priced lines — the same safe, proven Register shape used throughout this session, rather than a "resolve the one currently-active price across overlapping batches" computation (which would need to replicate fn_get_active_price's fallback logic — a reasonable v2 enhancement, not v1).

Filters

Column
GroupEntry No · Entry Date · Effective Date · Price Type · Customer · Location · Status
DetailProduct Code/Name · UOM · Cost Price · Selling Price · Margin %
Scoping note: a future "Effective Price List" (resolved, one row per product, as-of a date) is a genuinely different, more valuable report — flagged as a v2 candidate, not silently substituted for what's built here.
