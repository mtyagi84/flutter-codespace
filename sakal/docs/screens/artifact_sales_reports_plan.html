Sales Module · Reporting Blueprint

Twelve reports, the full customer journey

Sales already has a live Gross Profit engine (Sales Register, migration 127) — cost/revenue/margin are already real, posted-consistent data, just never grouped by Item, Invoice, Customer, or Salesperson. This maps those five reuses plus the seven genuine gaps — Quotation, Order, Delivery, and Collections have zero reports today — cross-checked against Finance's own AR ageing and Inventory's own movement analysis so nothing here duplicates them.

Real finding Gross Profit isn't new plumbing to build — rid_sales_invoice_lines.cost_price is already the SAME value the Cost-of-Sales voucher posts with, and v_sales_details_base already computes gross_profit/gross_profit_percent per line. Reports 01-05 below are new ways to GROUP that existing, posting-consistent data — not a new cost engine.

09

Open Sales Orders

Tabular

Orders still in play — status-based, not a quantity-fulfillment gap. Deliberately NOT modeled like Purchase's own Pending PO report.

Filters

CustomerSales PersonLocation Order ModeAging over N days
Column
Order No · Date · Days Open · Customer · Sales Person · Status · Grand Total
Real schema finding: Sales Delivery links to the ORIGINAL INVOICE, never to the Order directly — rid_sales_order_lines.delivered_qty is never actually written by any function in this build. A qty-gap report (like Purchase's Pending PO) would always show zero progress, so this report is scoped to order STATUS instead — "not yet Delivered or Cancelled."
